##### 一、这个项目是什么

- **提示词层**（`cordis.patch.yml` 的 `persona.prefix`）：人设、意图分流、固定输出格式、卡住/跳过；

1. **日志是唯一真源**：状态全部从会话日志折叠，不新增事件类型、不用 `storage`、不注册投影；

##### 0.4.0 会话连续性（摘要 + 暂停/恢复）

###### 解决什么问题

现在长会话有两个体验缺口：

1. 聊到后面，用户和模型都容易忘了“总共几步、做完几步、跳过几步”。
2. 用户说“先停一下，我晚点继续”时，没有明确的“暂停点”；模型可能继续往下讲。

注意：这不是“跨会话续接”。进度仍然只跟当前会话绑定，关闭后重开同一个会话可以继续，换新会话不接（Q4 A 不变）。

###### 用户会看到什么

状态块里多一行：

```
【进度摘要】已完成 3/7 步（跳过 1，剩余 3）；当前第 2/4 板块；本步失败 0；检索 2 次
```

暂停后，状态块变成：

```
【当前阶段】已暂停
【暂停位置】第 2/4 板块，第 1/2 步：把这个文档保存到桌面
【暂停备注】今天先到这，下次从「另存为」继续
【进度摘要】已完成 1/2 步（剩余 1）；本步失败 0
```

然后只提示“说『继续』后调用 `coach_pause({action:"resume"})`”。恢复后回到暂停前的步骤和阶段，旧证据**不作废**（这点和 `coach_back` 相反）。

###### 实现骨架

- 新增驻留相位 `PAUSED`（第 11 个相位）。
- 新增 **1 个工具** `coach_pause`，用 `action: "pause" | "resume"` 区分：
  - `pause`：允许在 `INIT` / `CHECK_TOOL_AVAILABILITY` / `INSTALL_TOOL` / `WAIT_FEEDBACK` / `VERIFY_DONE` / `DEGRADED`；记录 `{ at, fromPhase, stepKey, note }`，进入 `PAUSED`。
  - `resume`：只允许在 `PAUSED`；回到 `fromPhase` 和原来的步骤，记录 `resumedAt`。
- `PAUSED` 期间，除 `coach_pause(resume)` 外的教练工具全部拒绝，状态块不再显示【请执行】，避免模型“暂停了还在讲课”。
- `【进度摘要】`由 `core/` 纯函数计算：完成/跳过/剩余、当前板块、本步失败次数、检索次数；必须用 `effectiveSinceBack` 口径，回退前的结论不算完成。
- 暂停备注由模型在 `pause` 时写，长度截断；恢复时在工具结果里回显一次，状态块恢复成正常步骤块。
- `stateVersion` 升到 **8**；`PAUSED` 加入驻留相位；工具数 8。

###### 验收 A13

| # | 场景 | 通过标准 |
|---|---|---|
| A13-a | 在等待反馈时暂停 | 进入「已暂停」；`coach_verify` / `coach_advance` 被拒；重复 pause 被拒 |
| A13-b | 关闭 DSH 后重开同一会话 | 仍是「已暂停」；`resume` 回到原步骤/阶段；旧证据还在，可继续核查 |
| A13-c | 在安装分支里暂停 | `resume` 后仍留在安装分支，不丢 `originalGoal` |
| A13-d | 摘要计数 | 有跳过、有回退时，完成/剩余数字与状态一致 |
| A13-e | 暂停备注 | 暂停块显示备注；恢复后不残留成当前步骤内容 |

###### 风险与边界

- **死角的可能**：暂停后如果模型不调 `resume`，会话会停住。缓解：暂停块只给这一条出口、所有被拒工具的错误文案都指向 `resume`，用户说“继续”即可。
- **工具形状**：用一个 `coach_pause` 而不是两个工具，是为了少一份工具 schema 的常驻 token；如果你觉得“一个工具两种动作”容易混淆，可以改成 `coach_pause` + `coach_resume` 两个工具（工具数 9）。
- 不做跨会话、不做 `storage`；暂停只保当前会话。

##### 0.4.1 脚手架递减

###### 解决什么问题

现在不管用户是“从未用过”还是“熟练想进阶”，【请执行】的详细程度差不多。新手需要“点左上角文件 → 另存为”，熟手会觉得被当小孩；而且一直手把手，用户很难真正独立。

###### 用户会看到什么

状态块多一行：

```
【支撑等级】2（给要点）：只给关键操作和目标，不逐键指路；核查标准不变
```

三个等级：

| 等级 | 叫什么 | 【请执行】给到什么程度 |
|---|---|---|
| 3 | 手把手 | 具体菜单、按钮、快捷键，按顺序点 |
| 2 | 给要点 | 目标 + 关键操作，具体位置让用户自己找 |
| 1 | 放手 | 只给目标、约束和合格标准，操作由用户自己规划 |

**核查标准、证据要求、固定格式一律不变**——只变“提示的详细程度”，不放松“做对了没有”。

###### 怎么算（代码算，不靠模型自觉）

- 初始等级：从未用过 = 3，会基础 = 2，熟练想进阶 = 1，未知 = 2。
- 按**板块**结算：
  - 上一板块所有步骤都“一次过”（没有失败、没有跳过、没有回退），且板块至少 2 步 → 降一级（最低 1）。
  - 上一板块有跳过/回退，或有步骤失败 ≥2 次 → 升一级（最高 3）。
  - 板块内当前步骤失败到 2 次 → 立即升一级，本板块内不再降。
- 只读现有状态（`userLevel`、`verifications`、`skips`、`backs`、`failedAttempts`），不新增工具、不新增相位、不改折叠语义，`stateVersion` 保持 8。

###### 验收 A14

- 单测覆盖：初始映射、连续一次过降级、失败/跳过/回退升级、上下限、板块内只升不降。
- 实机：熟练用户连续过 3 步后，状态块显示等级 1；抽 3 步看【请执行】不再逐键指路。
- 回归：`coach_verify` 四条前置、`coach_advance` 闸门完全不变。

###### 风险

- **过早放手**：用“整个板块一次过 + 至少 2 步”做门槛，避免一步就降。
- **模型不遵守**：等级由插件计算并写进状态块，人设只负责“按等级调整详细度”；如果实机发现模型仍写得很细，再考虑加一条更硬的格式约束。
- 用户随时可以说“讲详细点”，模型可以临时展开，但等级本身不因此改变。

##### 0.4.2 成本控制

###### 解决什么问题

长会话的钱主要花在：反复检索、状态块越来越长、检索正文塞进状态、读文件内容。目标不是“省到不能用”，而是**有上限、可预期**。

###### 用户会看到什么

状态块多一行：

```
【用量】本步检索 1/3；本会话检索 5；核查 2 次
```

检索超过上限时，工具返回明确提示，而不是继续烧：

```
本步检索次数已到上限（3）。先使用已有【检索缓存】；确需继续，请先推进到下一步，或让用户提供截图/报错。
```

###### 三刀

1. **检索上限**：`maxResearchPerStep` 默认 **3**；`research` 条目记录 `stepKey`，同一一步第 4 次调用被拒（`COACH_RESEARCH_BUDGET`）。失败调用也计数——它同样花了钱。
2. **状态块预算**：`maxStateBlockChars` 默认 **4000**。超预算时按固定顺序裁：先裁【检索缓存】、再裁【回退记录】/【跳过提醒】、再裁历史证据；**当前步骤、合格标准、核查结论、错误提示永远不裁**。
3. **检索正文**：`researchContentMaxChars` 默认 **2000**，只截“存进状态”的正文；工具单次返回给模型的文本不变。

`research` 增加 `stepKey`、正文截断会改变折叠结果，`stateVersion` 升到 **9**；工具数仍是 8。

###### 验收 A15

- 同一步第 4 次 `coach_research` 被拒，错误码与提示正确；换到下一步后额度重置。
- 构造一个“多次跳过 + 多次回退 + 多条检索”的长状态，状态块不超过 4000 字符，且当前步骤/标准/结论仍在。
- 【用量】数字准确；`research` 存的正文不超过 2000。
- A1–A13 回归不退化。

###### 风险

- 上限太紧会挡住正常查证。默认 3 次/步，Config 可调；错误文案给出“先用缓存 / 先推进 / 让用户给证据”三条出路。

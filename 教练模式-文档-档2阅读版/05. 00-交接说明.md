## 六、安装与更新机制（**先读这一节，这里出过事**）

### 6.1 `install_bundle` 实际做了什么

它不是"把目录复制进 profile"，而是：

1. 把 bundle 目录**打包成 `local-coach-mode-<version>.tgz`**（放在 bundle 目录内）；
2. 在 profile 的 `package.json` 里写入一条 **`file:` 依赖**指向那个 tgz：
   ```json
   "dependencies": {
     "@local/coach-mode": "file:C:/Users/<user>/Documents/deepseek-harness/default-workspace/coach-mode-bundle/local-coach-mode-0.1.0.tgz"
   }
   ```
3. 由 pnpm 把 tgz 解包进 profile 的 `node_modules\@local\coach-mode\`。

### 6.2 已经发生过的事故（务必避免重演）

**`coach-mode-bundle` 目录曾经被清空**——6 个源文件全部消失，只剩空目录。
当时是靠 `node_modules\@local\coach-mode\` 里的安装副本恢复的（已恢复完毕，内容为最新版）。

由此得出三条硬性要求：

1. **动手之前先备份**：
   `coach-mode-bundle` → 复制一份为 `coach-mode-bundle-档0备份`（或任何不会被打包进去的名字）。
2. **不要把源目录清空或移走**。profile 里那条 `file:` 依赖指向 bundle 目录内的 tgz，
   源目录一旦不完整，覆盖安装就可能失败。
3. **不要直接改 `node_modules\@local\coach-mode\` 里的文件**——那是安装产物，
   下次安装会被覆盖，改了也不生效。

### 6.3 更新与重启

- 更新流程：**改源目录 → `install_bundle` 重新安装 → 重启 DSH**。
- **档 1 的重启要求比档 0 更硬**：档 0 只有 YAML 补丁，档 1 **首次引入 JavaScript 模块**。
  替换已安装的包需要重启才能加载新的 JS 模块代；只装补丁不重启可能看到旧代码。
- 覆盖安装若报错，可先 `plugin_manager` 的 `remove_bundle` 卸载，再重新 `install_bundle`。

## 八、会话日志怎么读（验收证据的获取方式）

SPEC 第 12.3 节要求验收附**日志路径与事件 `seq`**，所以你必须会读日志。

### 8.1 怎么拿到日志

在 Web 会话里输入 **`/export`**，会下载一个 zip，里面是 `session.v4.jsonl`
（若有子代理，还会有 `subagents\...\session.v4.jsonl`）。

### 8.2 格式要点

- JSONL：每行一个 JSON 事件，用 `type` 字段区分。
- 关键事件类型：

| type | 取内容的位置 |
|---|---|
| `user/message` | `data.content[]`；**只有 `data.source.kind === 'user'` 才是真人输入**，其余是 runtime-context 注入 |
| `assistant/message` | `data.message.content[]`（注意嵌套层级与 user 不同） |
| `tool/call` | `data.name` + `data.arguments`（**是 JSON 字符串，要再 parse 一次**） |
| `tool/result` | `data.result` / `data.content` |
| `agent-preset/selected` | 实际生效的 preset |
| `system/message` | 系统提示词，可用来确认教练人设是否注入 |

### 8.3 ⚠️ 一个把我坑过的陷阱

**`session` 头里的 `agentPreset` 字段是「建会话时的默认值」，不是实际生效的 preset。**
实际生效的要看 `agent-preset/selected` 事件。

我曾据此误判"3 个会话跑在标准模式下"，实际上那 5 个会话全部是教练模式。
统计脚本里**不要用 `session.agentPreset` 判断模式**。

## 1. 我的意图（为什么做成现在这样）

### 1.1 为什么按三个版本走

用户 2026-10-18 拍板：**0.4.0 会话连续性 → 0.4.1 脚手架递减 → 0.4.2 成本控制**。
我没有把三项塞进一个版本，原因是：

- 摘要和暂停共用状态块与进度信息，合并只升一次 `stateVersion`；
- 脚手架只改“提示详细度”，不碰冻结语义，可以独立验收；
- 成本控制要给 `research` 加 `stepKey`，会再升一次 `stateVersion`，放最后最干净。

### 1.2 为什么摘要先做“确定性”的

我选择先做**代码计算的进度摘要**（完成/跳过/剩余/当前板块/失败/检索次数），加上暂停时由模型写的一句备注，
而**没有**先做一个“模型写学习笔记”的新工具。理由：

- 不增加工具 schema 的常驻 token（我们正在为成本发愁）；
- 摘要数字必须可靠，代码算比模型写稳；
- 如果实机发现“数字够了但叙事不够”，再补 `coach_summary` 工具也不迟（那会是 0.4.x 或 0.5）。

### 1.3 为什么暂停只用一个工具

`coach_pause({ action: "pause" | "resume" })` 一个工具、两个动作。
拆成两个工具会让工具数从 8 变 9，每个请求都多一份 schema 成本；
一个工具 + `enum` 足够清楚，错误也会指出该用哪个 action。**不要为了方便擅自拆成两个工具**。

暂停做成独立相位 `PAUSED`，而不是状态里的一个 flag：这样“其它工具被拒”由同一个阶段闸门保证，
不需要每个工具各自记得检查 flag；出口只有一个 `resume`，不会变成死角。
暂停**不作废证据**——它只是中断，不是“重做”；只有 `coach_back` 才让旧结论失效。

### 1.4 我坚持的三条边界

- **状态机要硬，提示词要软**：能写进代码 `if` 的（相位、前置、失效、预算）不写进提示词。
- **日志是唯一真源**：不新增事件类型、不用 storage、不注册投影；所有状态从日志折叠。
- **先有证据再改**：实机验收必须留会话 id + `seq`；不接受“应该可以”。

### 1.5 我刻意没做的事

- **不做跨会话续接 / `storage`**：Q4 A 只做同会话；暂停跟当前会话绑定。
- **不做 UI / slash / `/coach`**：Q6 A 本轮不做。
- **不做 `pwsh` / `bash` 守卫、适配器分层、`uncertain_topics`、`Config` schema**：0.5 再议。
- **不做 `CLARIFY_ERROR` / `DIAGNOSE_ERROR` 独立相位**：Q2 C 保持分支。
- **没有把 0.4.1 / 0.4.2 的代码提前写**：避免半成品跨版本污染；只有 SPEC §13 / §14 的规划。

### 1.6 我希望你继承的东西

- 用日志验收，不用“我觉得”；
- 不重开 Q1–Q7、D1–D11、R1–R16；
- 不放松 `coach_verify` 四条前置和 `coach_advance` 闸门；
- 加工具/相位前先问：**入口是什么？出口是什么？模型不配合会不会变成死角？**
- 改 `core/` 前先写测试；改折叠语义必须升 `stateVersion`；

### 4.2 0.4.1：脚手架递减（下一刀）

**目标**：按学习者实际表现调整【请执行】的详细程度，**不放松任何核查标准**。

设计在 SPEC §13，要点：

- 三个等级：3 手把手（具体菜单/按钮/顺序）、2 给要点（目标 + 关键操作）、1 放手（只给目标/约束/标准）。
- 初始：从未用过 = 3，会基础 = 2，熟练想进阶 = 1，未知 = 2。
- **按板块结算**：
  - 上一板块**至少 2 步**且全部“一次过”（无失败、无跳过、无回退）→ 降一级（最低 1）；
  - 上一板块有跳过/回退，或有步骤失败 ≥2 次 → 升一级（最高 3）；
  - 板块内当前步骤失败到 2 次 → 立即升一级，本板块内不再降。
- 只读现有状态（`userLevel` / `verifications` / `skips` / `backs` / `failedAttempts`）；
  **不新增工具、不新增相位、不改折叠语义，`stateVersion` 保持 8**。
- 状态块加 `【支撑等级】2（给要点）：只给关键操作和目标；核查标准不变`。
- 人设加一段“按支撑等级调整【请执行】的详细度；等级降低不等于放松核查”。

建议实现位置：

## 5. 不要重犯的坑（2.5 新增）

1. **工具定义必须有 `description`**：`coach_back` 曾漏写，宿主写 `request/header` 时因
   `description: undefined` 硬失败（`carries non-JSON-serializable data`）。
   `tool-shape.test.js` 会检查所有工具的 `name`/`description`/schema 是无损 JSON。
   **新增工具必须跑它和冒烟。**
2. **`PAUSED` 是“拒绝一切”的相位**：新增工具/动作时，确认它在 `PAUSED` 被拒；
   特别是有“旁路”的入口（例如 `coach_plan` 的安装分支早退），必须在 `PAUSED` 显式挡住。
3. **暂停不作废证据，回退才作废**：两者语义相反，别把 `effectiveSinceBack` 用到暂停上。
4. **摘要的“完成”必须用 `effectiveSinceBack`**：回退后的旧“通过”不能算完成。
5. **`stateVersion` 只在折叠语义变化时升**：0.4.0 升到 8；0.4.1 不该升；0.4.2 因 `research.stepKey`/截断升到 9。
6. **加教练工具要同步这几处**：`core/machine.js` 的 `COACH_TOOLS`、`index.js` 的 `TOOL_FACTORIES`、
   `_ref/coach-recheck.cjs` / `coach-accept.cjs` / `coach-evidence.cjs`、`test/tool-shape.test.js`、`_ref/smoke-coach.mjs`。
7. **相位/工具数变化要同步测试与文档**：`machine.test.js` 的 `PHASES` / `RESIDENT_PHASES`、README 的“11 状态 / 8 工具”、SPEC 头部。
8. **`PAUSED` 块不要显示【请执行】**：否则模型会“暂停了还在讲课”。
9. **不要只跑 `node --check`**：它查不出模型可见 schema 里的 `undefined`；跑单测/冒烟/`tool-shape`。
10. **不要动 `coach-mode-pack\`**：那是 0.3.4 的对外快照（给另一台电脑的交付包），

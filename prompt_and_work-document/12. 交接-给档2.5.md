## 1. 我的意图（为什么这样做）

### 1.1 我做的不是“把 12 个状态一次堆完”

档 2 的原始清单很大：12 个状态、检索、暂停/恢复、UI、摘要、脚手架、成本控制……
我没有按清单一路铺功能，而是按这个顺序走：

1. **先修 0.2.4 的实机死角**（空 `sections` 循环、非法 `kind`）；
2. **再上检索**（`RESEARCH` + `coach_research` + `research_cache`）；
3. **再上安装分支**（`INSTALL_TOOL`）；
4. **每次只加“有明确入口和出口”的东西**。

原因很直接：档 1 最大的教训是 **状态机把路堵死，模型就会卡在某个阶段干聊**。没有工具入口的
状态等于死角；没有出口的状态会卡死。档 2 不能再造这种死角。

### 1.2 我坚持的三条边界

- **状态机要硬，提示词要软。** 能写进代码 `if` 的（前置条件、阶段、新证据规则）不写进提示词；
  只能靠模型判断的（反馈模糊/明确、检索来源质量）留在提示词层。
- **日志是唯一真源。** 状态全部从会话日志折叠，不新增事件类型、不用 storage、不注册投影；
  所以重启、fork、回放都能重算。这条是 D3/D4，我没有破。
- **先修真实缺陷，再谈“更强制”。** A8–A12 的每一次改动都先有会话 id + `seq` 证据；
  不接受“应该可以”。

### 1.3 我刻意没做的事

- **不做 UI / slash / `/coach`**：Q6 A 已拍板本轮不做；D1 也不做会话内切换。
- **不做跨会话无缝续接 / `ctx.storage`**：Q4 A 只做同会话。
- **不把 `CLARIFY_ERROR` / `DIAGNOSE_ERROR` 做成独立相位**：Q2 C 决定先留在
  `WAIT_FEEDBACK` 里当分支；现在仍是 10 个相位，不是 12 个。
- **不做 `Config` schema**：导出它必须 import `@deepseek-ai/schemastery`，与 R9 冲突。
- **不给 `pwsh` / `bash` 加守卫**：还没解决“只读命令核查的替代通道”，先不动。

这些不是遗漏，是边界。**不要因为“清单上还有”就顺手补上。**

### 1.4 为什么停在 0.3.2

A12 的机制通过了，但暴露了一个真实的 UX 问题：**用户已经装好 Blender，模型仍然按“未安装”
走了 3 步安装确认**。这不是状态机相位写错，而是“可用性判断”和“已装好后的早退”缺失。

同时我的上下文已经到 60% 左右。继续在压缩边缘改 `core/`，风险大于收益。
所以我选择：**把 0.3.2 做成可交接的稳定点，把安装体验问题写清楚，交给下一个人。**

### 1.5 我希望你继承的东西

- 用日志验收，不用“我觉得”；
- 不重开 Q1–Q7 和 D1–D11/R1–R16；
- 不为了“更强制”放松第 5.2 节四条前置条件；
- 加状态前先问：**入口是什么？出口是什么？模型不配合会不会变成死角？**
- 改 `core/` 前先写测试；改折叠语义必须升 `stateVersion`。

## 5. 不要重犯的坑（清单）

1. **任何 `.js` 都不许 `import '@deepseek-ai/*'`**：宿主包在 `app.asar`，profile 的 bundle
   解析不到；一行 import 会让整个 preset 显示「加载失败」。用 `tools/define-tool.js`、
   `config.js` 的手写归一化。
2. **不要新增会话事件类型**：`Session.append()` 不能设 `ignorable`，写进去的会话可能无法重开。
   状态只能从既有事件折叠。
3. **不要用 `ctx.storage` 做跨会话续接**：Q4 A 没批准；同会话重开就是“恢复”。
4. **不要改 `03` 和 01–11 的历史正文**：`03` 冻结；01–11 是历史快照。新内容加到
   `../SPEC-档2-教练模式.md` 或本文件/新版本块。
5. **不要手写 profile 的 `package.json` / `cordis.patch.yml`，不要在 profile 里跑 pnpm**：
   安装只走 `plugin_manager.install_bundle`。
6. **不要动桌面归档和无关目录**（`git-practice`、`bili-fav`、`house`、`.bili_cookie_check`）。
7. **不要用 PowerShell 的 `Set-Content -Encoding utf8` 改 `package.json`**：会加 BOM，
   `JSON.parse` 直接炸。用 `edit` 工具或 Node 写。
8. **人设里不要引用未核对的 `{{...}}` 变量**：0.2.1-rc.1 只剩 `provider` / `model`；
   引用不存在的变量是每轮硬失败，不是降级。
9. **人设固定格式字段之间必须空行**：DSH 渲染器只认硬换行，去掉空行会挤成一行。
10. **加状态/加工具必须同时想入口和出口**：没有入口=死角，没有出口=卡死。
11. **不要放松 `coach_verify` 的四条前置 + 新证据规则**：这是档 1 唯一真正“物理”的东西。
12. **改折叠语义必须升 `stateVersion`**：当前 5；0.3.3 如果受控早退，按实际升 6。
13. **`coach-recheck.cjs` 的 `COACH_TOOLS` 已补 `coach_research`**；如果再加教练工具，
    记得同步 `coach-recheck` / `coach-accept` / `coach-evidence`，否则复核会漏报。
14. **分支会话会复制旧事件**：A9retest 前 89 个事件是 0.3.0 的；看到旧 `consent`/旧状态块
    不要误判为“当前版本没改”。
15. **安装/重启两件事都要做**：改声明行必须重装；改 JS 也要重启才加载新模块代。
